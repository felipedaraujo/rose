## Rules

This section describes how this file works.

1. **Sections**
   - **Today** — tasks actively being worked on or planned for today.
   - **Backlog** — tasks not yet started, waiting to be picked up.
   - **Done** — completed tasks, kept for reference and history.

2. **Columns** (used in Today, Backlog, and Done)
   - **ID** — a unique, sequential identifier (e.g. `T-001`, `T-002`). IDs are never reused, even after a task is deleted.
   - **Title** — a short, clear description of the task.
   - **Started At** — the date work began, in `YYYY-MM-DD` format. Empty for tasks in the Backlog that haven't started.
   - **Due** — the target completion date, in `YYYY-MM-DD` format. May be empty if there is no deadline.
   - **Links** — related URLs, documents, issues, or PRs. Multiple links are separated by commas.

3. **Workflow**
   - New tasks are added to **Backlog** with a new ID and (optionally) a due date.
   - When work starts on a task, move it to **Today** and fill in **Started At**.
   - When a task is finished, move it to **Done**, keeping all its column values.
   - At the start of each day, review **Today**: move unfinished tasks that won't be worked on back to **Backlog**, and pull in the next tasks from **Backlog**.

4. **Conventions**
   - Keep one task per row; a task lives in exactly one section at a time.
   - Newest tasks go at the top of **Backlog**; most recently completed tasks go at the top of **Done**.
   - Dates always use the `YYYY-MM-DD` format.
   - If **Done** grows too large, older entries may be archived to a separate file (e.g. `TASKS-ARCHIVE.md`).
